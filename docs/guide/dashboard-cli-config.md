# 9. Web Dashboard 与 CLI

## 9.1 Dashboard 默认关闭

默认配置：

```toml
[dashboard]
enabled = false
listen = \

rules:
    - event: recovery.exhausted
      severity: critical
      channels:
        - primary-webhook
```

需要注意：

1. 代理健康检查应尽量区分代理认证失败、连接失败和目标服务异常。
2. 如果代理并非 Tunnel 的必要依赖，则不应声明 Required。
3. HTTP 探测和上述特定插件属于后续阶段能力。
4. 第一版的配置验证器可以先定义完整配置模型，但未实现的资源类型必须报出清楚的能力缺失错误，不能假装已经运行。
5. 恢复动作必须与插件能力声明匹配。

## 10.3 配置加载过程

1. 解析配置。
2. 验证版本。
3. 验证结构。
4. 验证资源 ID。
5. 验证依赖引用。
6. 验证依赖图。
7. 验证恢复动作引用。
8. 验证插件能力。
9. 验证权限与风险策略。
10. 验证通知渠道配置。
11. 验证数据库迁移兼容性。
12. 创建或更新运行时资源注册表。

配置验证失败时必须指出具体字段和原因。

# 10. 配置规范

## 10.1 基本原则

配置必须：

- 可验证。
- 可版本化。
- 能提供明确错误路径。
- 不允许未知字段被静默解释成有效配置。
- 支持安全的凭据引用。
- 支持资源之间的显式依赖。
- 支持资源级恢复策略。
- 支持全局预算和通知规则。

建议首版采用 TOML，或者 YAML，但第一版只选一种主配置格式。避免同时维护两种格式。
