## 六、审计过程简述

1. 通读 `README`、`docs/**`（guide + adr）、`docs.yml`、`gh repo view` 描述行，逐条提取对实现的断言。
2. 对每条断言在源码中定位证据（`file:line`），并先确认路径存在再下「未实现」结论。
3. 按三桶分类（A 文档超前于码 / B 码超前于文档 / C 描述不符），并给严重度（P0 最危险 over-claim）。
4. 以源码为准修复：改文档（删除/标注 over-claim、补充缺失、纠正不符）；不改码（无 ADR 要求改码的冲突项）。
5. 复跑 `pnpm docs:build`（本地 VitePress 构建）确认文档站可构建、无坏链引入。
6. 生成本报告；剩余非缺陷事项写入 `todo.md`。
